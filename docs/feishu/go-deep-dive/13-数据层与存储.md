# 13 数据层与存储：model 领域模型、PG/Redis/ES/Supabase 四套存储与迁移

> 一句话定位：本篇盘点项目所有「数据落脚地」——领域实体与仓储端口（model 模块）、Postgres 连接与 GORM（core/database + repository/postgres）、Redis（见 [09-Realtime与WebSocket](09-Realtime与WebSocket.md)）、Elasticsearch（交易域内手搓 REST 客户端）、Supabase PostgREST（core/supabase + repository/supabase），以及启动时 SQL embed + AutoMigrate 的建表清单；阅读前置：懂 go.work 四模块依赖方向（app→{common,core,model}、core→{common,model}）。

## 0. 通俗理解

数据层像一个集团的**档案体系**：

- **model/entity** 是「档案盒标签」：只描述每张表长什么样、每个枚举数字什么意思，不知道也不关心数据库在哪。它是全工作区最底层的共享词汇表（连 Flutter 对齐用的 JSON tag 都在这）。
- **model/repository** 是「查档窗口告示」：只写接口（要能做哪些操作），不写怎么做。
- **core/database** 是「大楼的水电总闸」：打开 Postgres、Redis 连接并配好连接池。
- **repository/postgres、repository/redis、repository/supabase** 是「具体档案室」：拿着告示去真正的库里干活。
- **Elasticsearch** 是「外置检索机」：交易域嫌 Postgres 全文搜索弱，自己用标准库 net/http 搓了个 ES 客户端。
- 建表靠两路：**内嵌的幂等 SQL 文件**（`//go:embed`，管复杂改造）+ **GORM AutoMigrate**（管新表兜底）。

业务表统一 `wys_` 前缀；历史遗留的 `users / transactions / analytics_records / auth_refresh_tokens` 等不带前缀。

## 1. 存储全景

| 存储 | 用途 | 连接/客户端位置 | 主要内容 |
|------|------|------------------|----------|
| Postgres | 业务主库（本地 Auth 后全部业务数据） | `core/database/postgres.go`（GORM） | users、wys_* 全部业务表、analytics_records |
| Redis | 会话、WS ticket、事件流、presence、限流、Pub/Sub | `core/database/redis.go`（go-redis v9） | 见 09 篇 §4 |
| Elasticsearch | transactions 全文检索 | **无独立包**；`app/internal/transaction/repo_es.go` 内手搓 REST | 索引 `transactions` |
| Supabase | Cloud 模式：Auth + PostgREST profiles | `core/supabase/`（supabase-go + gotrue） | Auth 用户、`profiles` 表（RLS） |
| RabbitMQ | 异步任务（非本篇重点） | `core/queue/` | push/sms 等 |

## 9. Elasticsearch：在哪个包、怎么用

**结论先行（grep 全仓 `elasticsearch` 的事实）**：没有独立 ES client 包；唯一业务封装在交易切片内 [repo_es.go](file:///Users/qpy/Desktop/github/my_go_study/app/internal/transaction/repo_es.go)。文件头注释自述：「用最小 HTTP REST 访问 Elasticsearch（**不引入官方 Go client**）。原 internal/repository/es/transaction_store.go。TransactionStore → ESStore」。配置只有一个 URL：`common/config.ElasticsearchConfig{URL}`，`Enabled()=URL 非空`、`BaseURL()` 去尾斜杠；装配点在 main.go L285-293（`cfg.Elasticsearch.Enabled()` 时 NewESStore + EnsureIndex，失败只 warn：写路径降级、搜索 503；成功后 `transactionSvc.SetSearchStore`）。

| 函数/方法签名 | 职责 | 关键逻辑 |
|---------------|------|----------|
| `ESStore{base string; client *http.Client}` + `NewESStore(baseURL)` | 持 base URL 与 5 秒超时 http.Client | trim 尾斜杠；索引名常量 `TransactionsIndex="transactions"`（与 PG 表同名，但是 ES 索引） |
| `(s) EnsureIndex(ctx) error` | `PUT /transactions` 建 mapping | id long、**user_id keyword（强制隔离）**、type/category text+keyword 子字段、note text、amount double、date keyword；400 且体含 `resource_already_exists` 视为成功 |
| `(s) Index(ctx, *entity.Transaction) error` | `PUT /transactions/_doc/{id}` 全量覆盖（文档 id=交易主键） | nil 直接返回；指针字段解引用；非 2xx 返回截断 200 字节的错误体 |
| `(s) Delete(ctx, id) error` | `DELETE /transactions/_doc/{id}` | 404 视为成功（幂等） |
| `(s) Search(ctx, userID, q string, limit) ([]entity.Transaction, error)` | `POST /transactions/_search` | userID 必填（空报错）；limit 默认 20、上限 100；q 空→bool.filter.term user_id；非空→filter user_id + must.multi_match(note/category/type)；sort id desc；解析 hits._source 回实体 |
| `truncate(b, n)`（私） | 错误体截断 | 防日志爆炸 |

用法边界：搜索只信会话 user_id（与 HTTP RLS 口径一致）；交易 CUD 时 best-effort 同步 Index/Delete；ES 不可用时主链路（PG/PostgREST）不受影响。

## 13. 学习要点回顾

1. **模块边界就是数据边界**：entity/repository/provider 在 model 叶子模块定义，app 与 core 各自实现；model 永远 import 不到 GORM/Redis。
2. **表名三类前缀**：`wys_` 业务表；无前缀的历史/基建表（users、role、transactions、analytics_records、auth_refresh_tokens）；ES 索引与 PG 表同名但是两套存储。
3. **金额两套表示法**：钱包/会员用 int64 分（ParseYuanToFen 用 big.Rat 防浮点）；商城 numeric(10,2) 用 string 承载；分析宽表试验用 float64。
4. **软删两派**：多数业务表用可空 `deleted_at *time.Time` 手写过滤；GORM 自带 DeletedAt 基本不用。
5. **复合主键密集**：成员关系/关注/点赞/签到/购物车/权益等「关系表」几乎都是复合主键，天然防重。
6. **连接管理**：PG 连接池三参数 + 启动 5 次 ping 重试；GORM logger 固定 Info 全量 SQL（生产噪音点）。
7. **同一接口两套实现**：ProfileRepository 在 Cloud 走 PostgREST+RLS（WithUserToken），本地走 users 投影；supabase 版不支持改 phone 是真实差异。
8. **ES 是域内私有零件**：手搓 net/http REST、user_id keyword 强制过滤、CUD best-effort、无官方 client、无独立包——别在 core/ 找它。
9. **建表双轨制**：embed 幂等 SQL 管存量改造（改列/改名/迁数据），AutoMigrate 管新表兜底；启动顺序固定「探测旧表→SQL→Migrate」。
10. 代码注释也可能过时：after_sales 建表注释与 embed 清单不一致，以代码实际执行路径为准。
