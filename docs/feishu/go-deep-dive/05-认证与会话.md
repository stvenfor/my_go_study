# 05-认证与会话

> 一句话定位：本文讲清 BFF 的「门禁系统全套图纸」——local（本机 Postgres）与 supabase（云 GoTrue）两套可切换认证后端、UUID JWT/云 token 的签发校验、Redis 单设备登录互踢、白名单多端豁免、TTL=0 不过期、refresh 轮换与 logout 全链路。所属模块：common（jwt/auth/config）+ app（usecase、delivery/http 的 handler 与 middleware、repository/redis）。阅读前置：先读 [04-HTTP路由与中间件](04-HTTP路由与中间件.md) 了解中间件链与统一错误码。

## 通俗理解

把账号体系想成酒店入住：

- **access token** 是房卡：开门（调业务 API）时刷一下。local 模式的房卡是酒店自己印的 HS256 JWT（UUID 房号，默认 72 小时有效）；supabase 模式的房卡是连锁集团（Supabase GoTrue）发的，开门时要打电话给集团前台问「这卡还有效吗」（HTTP 调 `/auth/v1/user`）。
- **refresh token** 是续住凭证：房卡过期不用重新登记身份，拿它换新卡。local 模式它是 32 字节随机串的 SHA256 存库行（30 天、**用一次即作废轮换**）；supabase 模式由云端管理。
- **单设备 session** 是酒店规定「同一账号只给一间房」：Redis 里每个 user_id 只存一条 `{session_id, device_id}`，新设备登录直接覆盖，旧设备下次刷卡收到 10021「账号已在其他设备登录」。
- **白名单/测试号**是「长包房/VIP」：不落 Redis、不互踢，多端同时在线。
- **TTL=0** 是「房卡记录没有到期日」：Redis key 永久驻留，只在主动 logout 或被新设备顶替时删除（但 JWT 房卡本身仍按 72 小时过期，需走 refresh）。
- **账号状态门**是楼层保安：注销（deleted_at）/停用（status=1）的客人房卡再有效也拦下（403）；但锁定（status=2，连续输错密码 5 次锁 15 分钟）不赶出已在房内的客人。

源码主锚点：`app/internal/usecase/{local_auth_usecase,supabase_auth_usecase,device_session_usecase,account_login,phone_otp_usecase,wechat_auth_usecase,huawei_auth_usecase,user_usecase}.go`、`app/internal/delivery/http/handler/user_handler.go`、`common/jwt/jwt.go`、`common/auth/supabase.go`、`app/internal/repository/redis/session_repo.go`、`model/repository/session_repository.go`。

## 1. 全景：两套后端 + 一条统一会话链

进程启动时由配置 `auth.provider`（`common/config/config.go#L156-L187`）二选一，在 `app/cmd/api/main.go#L166-L283` 装配：

| 维度 | local（`provider: local`） | supabase（默认/空值） |
| --- | --- | --- |
| 用户数据 | 本机 Postgres `users` 表（`model/entity/user.go`，UUID 主键 user_id） | Supabase Cloud（GoTrue），本地不存密码 |
| access token | 自签 HS256 JWT，`sub=用户 UUID`，claims 带 email/username | GoTrue 发的 JWT，**不本地验签**，每个受保护请求 HTTP 调 `/auth/v1/user` 校验 |
| refresh token | 32 字节随机串，SHA256 存 `auth_refresh_tokens` 表，30 天，一次性轮换 | GoTrue refresh_token，调 `Auth.RefreshToken` 换新 |
| 登录失败锁定 | 有：5 次失败锁 15 分钟（status=2 + locked_until） | 无本地锁定，行为取决于云端 |
| 账号注销/停用门 | `LocalAuthUsecase.AllowsRequest` 查库（Gate 生效） | 无 Gate（accountGate 为 nil） |
| 手机 OTP | 仅 dev 测试号：固定验证码，自动建号 | 仅 dev 测试号：Admin(service_role) 建号后邮箱密码登录 |
| 微信/华为登录 | 支持（OAuth 换 unionID/openID → 本地找/建号） | 不支持（usecase 不构造，handler 回 503） |
| 会话中间件 | `middleware.LocalSessionAuth`（ParseUUID + Redis Validate） | `middleware.SupabaseSessionAuth`（HTTP 校验 + Redis Validate） |

**关键：单设备 session 机制两套共用。** 不管哪套后端，登录成功后 handler 都调 `DeviceSessionUsecase.IssueOnLogin` 写 Redis；每个受保护请求都过 `sessionUC.Validate`；上下文身份键完全相同（`supabaseUser`/`accessToken`）。

抽象契约在 `usecase/local_auth_usecase.go#L23-L35`：

| 接口 | 方法 | local 实现 | supabase 实现 |
| --- | --- | --- | --- |
| `SessionAuth` | `Register / Login / RefreshToken / Logout` | `*LocalAuthUsecase` | `*SupabaseAuthUsecase` |
| `PhoneOTPAuth` | `SendPhoneOTP / VerifyPhoneOTP` | `*LocalAuthUsecase`（同结构体实现） | `*PhoneOTPUsecase` |
| `WeChatLoginAuth` | `LoginWithWechatCode` | `*WeChatAuthUsecase`（包一层 local） | nil |
| `HuaweiLoginAuth` | `LoginWithHuaweiCode` | `*HuaweiAuthUsecase`（包一层 local） | nil |

装配关系（main.go）：local 分支 `sessionAuthUC=phoneOTPUC=localAuth`，另建 wechat/huawei 两个外层 usecase，`accountGate=RequireActiveAccount(localAuth)`；supabase 分支 `sessionAuthUC=supabaseAuthUC`、`phoneOTPUC=NewPhoneOTPUsecase(...)`、accountGate 保持 nil。

## 2. 配置开关：provider / TTL=0 / 白名单 / dev bypass

| 配置/方法 | 含义 | 坑/备注 |

| `DevTestSessionExempt(appEnv,email)` | 测试号多端豁免：bypass 开 + 邮箱是 `{数字}@dev.test.local` 且号码在测试号列表 | local OTP 建号邮箱正是此后缀，故测试号天然多端 |
| `DevTestDisplayName/AvatarURL` | 测试号固定展示名（测试甲…戊）与 picsum 头像 | 方便双端 IM 区分 |

## 4. DeviceSessionUsecase：单设备登录核心

源码锚点：`app/internal/usecase/device_session_usecase.go`（全文 202 行）。存储端口在 model 叶子模块：`model/repository/session_repository.go` 的 `SessionRepository{Get,Save,Delete,ListActiveUserIDs}` 与 `DeviceSession{SessionID,DeviceID,Platform,CreatedAt}`（JSON snake_case）。

哨兵错误与文案（L16-L26）：

| 哨兵/常量 | 值/文案 | 触发位置 |
| --- | --- | --- |
| `ErrSessionInvalid` | "session invalid" / 「会话无效，请重新登录」 | 缺头、Redis 无记录、同设备 session_id 不符 |
| `ErrSessionReplaced` | "session replaced by other device" / 「账号已在其他设备登录，请重新登录」 | Redis 记录属于别的设备 |
| `ErrInvalidPlatform` | platform 非 android/ios | 签发/续期 |
| `ErrInvalidDeviceID` | device_id 空 | 签发/续期 |
| `MsgSessionInvalid` / `MsgSessionReplaced` | 中文文案 | 中间件与 handler 共用 |

方法级表：

| 方法签名 | 职责 | 关键逻辑/坑 |
| --- | --- | --- |
| `NewDeviceSessionUsecase(sessions, cfg, appEnv)` | 构造 | appEnv 决定测试号豁免 |
| `IsExempt(userID, email) bool` | 是否豁免单设备 | 显式白名单（`cfg.IsSessionExempt`）OR 测试号豁免（`cfg.DevTestSessionExempt`，要求非 prod 环境） |
| `IssueOnLogin(ctx, IssueSessionInput) (sessionID, error)` | 登录签发 | trim/校验 device_id 非空、platform ∈ {android,ios}、userID 非空；生成 UUID v4 session_id；**豁免账号只返回 id 不落库**；普通账号 `Save(uid, session, SessionTTL())`——新登录直接覆盖旧 key，即互踢动作本身 |
| `Validate(ctx, userID,email,sessionID,deviceID) error` | 每次受保护请求校验 | 豁免直接 nil；两头缺失 → Invalid；Redis 无记录 → Invalid；**同 session_id 但 device_id 变 → 允许并回写新 device_id**（注释：iOS 模拟器占位 id 升级为稳定 id）；device_id 不符 → Replaced；同设备 session_id 不符 → Invalid（注释：session 过期，客户端应 refresh 而非视为互踢） |
| `RevokeOnLogout(ctx, userID,email,sessionID,deviceID) error` | 登出 | 豁免 no-op；先 Validate 再 `Delete(uid)`——即只能踢掉自己当前会话 |
| `RenewOnRefresh(ctx, RenewSessionInput) (newSessionID, error)` | refresh 时续期 | 校验 userID/deviceID/platform（platform 空时默认 `"ios"`）；豁免账号：客户端带了 session_id 就原样返回，否则发新 id 不落库；普通账号：Redis 无记录 **或** 同设备 **或** 客户端 session_id 与库存一致 → 发新 session_id 并 Save 续 TTL；否则 Replaced |
| `saveDeviceSession(...)`（未导出） | Save 包装 | 统一组装 DeviceSession 与 TTL |

判定真值表（普通账号，Redis 中记为 `(s0,d0)`）：

| 请求带 (session, device) | Validate 结果 | 含义 |
| --- | --- | --- |
| (s0, d0) | 通过 | 正常 |
| (s0, d1) | 通过 + 回写 d1 | 设备 id 升级 |
| (s1, d1) | ErrSessionReplaced（10021） | 别的设备登录过 |
| (s1, d0) | ErrSessionInvalid（10022） | 同设备但 session 过期/已轮换，去 refresh |
| 任意，Redis 无 key | ErrSessionInvalid | TTL 到期/被登出（TTL=0 时只会因 logout/顶替出现） |
| 缺 X-Session-ID/X-Device-ID | ErrSessionInvalid | |

Redis 实现（`app/internal/repository/redis/session_repo.go`）：

| 方法 | 行为 |
| --- | --- |
| key 规则 | `auth:session:{userID}`（一用户一 key，单设备语义的物理保证） |
| `Get` | `GET` + JSON 反序列化；`redis.Nil` 返回 `(nil,nil)` 而非错误 |
| `Save` | JSON 序列化后 SET；**ttl ≤ 0 时 `Set(...,0)` 永久 key**——TTL=0 的落地点 |
| `Delete` | DEL key |
| `ListActiveUserIDs` | SCAN（count 100，非阻塞）遍历前缀列出在线用户 |

## 5. LocalAuthUsecase：本机 Postgres 认证全函数

源码锚点：`app/internal/usecase/local_auth_usecase.go`（469 行）。数据表：`users`（凭证+状态同行，字段见 `model/entity/user.go`）与 `auth_refresh_tokens`（`model/entity/auth_user.go`：自增 id、user_id 索引、token_hash 64 位唯一索引、expires_at、created_at）。常量 `refreshTokenTTL = 30*24h`。

### 5.1 公开方法表

| 方法签名 | 职责 | 关键逻辑/坑 |
| --- | --- | --- |
| `Register(ctx, RegisterInput) (*SupabaseAuthOutput, error)` | 邮箱注册 | email 小写化，必须含 @、密码 ≥6；`findOpenByEmail` 查重（含 deleted_at IS NULL）→ `ErrUserExists`；bcrypt DefaultCost 哈希；`newLocalUser` 生成 UUID user_id、status=0、password_changed_at=now；成功即 `issueTokens`（注册自动登录） |
| `Login(ctx, LoginInput)` | 邮箱密码登录 | username 字段当 email 用，不含 @ 直接 `ErrInvalidCredentials`；查无此人 → `ErrAccountNotRegistered`；`loginBlockReason` 先拦注销/停用/锁定；bcrypt 比对失败：`applyFailedLogin`+落库→凭证错；成功：`applySuccessfulLogin` 清锁定+写 last_login_at→发 token |
| `RefreshToken(ctx, raw) (*SupabaseAuthOutput, error)` | refresh 轮换 | 对原始串 SHA256 后按 `token_hash` 查行；查无/过期 → 凭证错（**过期顺手删行**）；用户已删 → 删 token 行 + 未注册；用户停用 → **删该用户全部 refresh 行** + 停用；正常：先删当前行（一次性）再 issueTokens，完成轮换 |
| `Logout(ctx, accessToken) error` | 登出撤销 | 尽量 ParseUUID，成功则删该 user_id 全部 refresh 行；解析失败也返回 nil（不阻断登出） |
| `Deactivate(ctx, userID) error` | 账号注销 | 只写 `deleted_at=now`（软删），RowsAffected=0 → 未注册；再删全部 refresh 行。**不提供置 status=1 停用的接口**（entity 注释：停用只能库内维护） |
| `AllowsRequest(ctx, userID) error` | Gate 回调 | 查无/deleted_at 非空 → 未注册；status=1 → 停用；**status=2 锁定不拦**（锁定不打断已有会话，锁过期后下次登录成功即清 0） |
| `SendPhoneOTP(ctx, phone) error` | 发短信（占位） | 非 dev bypass 或非测试号 → `ErrPhoneLoginNotAvailable`；测试号 **no-op 直接 nil**（不真发短信） |
| `VerifyPhoneOTP(ctx, phone, otp)` | OTP 登录 | bypass + 测试号 + OTP 等于配置固定值；邮箱 `{数字}@dev.test.local`；不存在则建号（随机密码哈希、展示名/头像走配置）；存在则补齐展示名/头像；最后 issueTokens |
| `LoginOrRegisterWechat(ctx, openID, nickname, avatarURL)` | 微信找/建号 | 占位邮箱 `wx_{openid}@wechat.local`；新建随机密码、默认名「微信用户」（截 64）；已存在则仅在默认名/无头像时补资料 |
| `LoginOrRegisterHuawei(ctx, unionID, openID, phone, nickname)` | 华为找/建号 | 占位邮箱 `hw_{unionID}@huawei.local`，**先按邮箱查、查无且带手机号再按手机号查**（账号合并）；新建随机密码、有手机号则写 phone_verified_at；已存在：旧邮箱是 dev 占位或空时改为 hw 邮箱、补手机号与昵称；`openID` 显式 `_ = openID`（仅联调用，主键认 UnionID；UnionID 空时上层已用 openID 兜底） |

### 5.3 登录锁定策略（account_login.go）

| 常量/函数 | 值/行为 |
| --- | --- |
| `maxFailedLogins = 5`、`accountLockFor = 15min` | 阈值与时长 |

## 6. SupabaseAuthUsecase 与云端 OTP

### 6.1 SupabaseAuthUsecase 方法表

| 方法 | 职责 | 关键逻辑/坑 |

## 8. 中间件侧的鉴权（认证视角复述）

详细函数表见 [04](04-HTTP路由与中间件.md) §3，这里只串认证语义：

1. `LocalSessionAuth`（`middleware/local_session_auth.go`）：Bearer（`authctx.BearerToken`，无前缀也接受）→ `ParseUUID`（失败 401/10023）→ 组装 `SupabaseUser{ID:sub,Email}` → 读 `X-Session-ID`/`X-Device-ID` → `Validate`（失败经 `abortDeviceSessionError`：10021/10022）→ 写 `supabaseUser`+`accessToken`。
2. `SupabaseSessionAuth`：同构，区别是 token 经 `pkgauth.ValidateAccessToken` 联网校验，user 含云端 phone。
3. `abortDeviceSessionError`：两类会话错误统一 401 并打 `[auth] session replaced/invalid` 日志。
4. `RequireActiveAccount`：取上下文 user → `AllowsRequest`：空身份 401「未登录」，任何错误统一 403「账号不可用」（不区分未注册/停用）。仅 local 装配。
5. `authctx` 叶子包：域 handler 统一用 `SupabaseAuthContext(c)` 取 (user, token)，避免导入环。
6. 遗留 `middleware.Auth`（uint JWT）当前无任何路由挂载；`user_handler.go` 文件头注释称「遗留路由 /api/v1/user/profile 仍用自建 JWT」，但当前 router 包已无该路径注册（现存的是 `/api/v1/me/profile`，挂 SA 链）——注释指向的是已删除的老路由，属过期注释。

## 9. 全链路时序

### 9.1 注册/登录（以 local 登录为例）

1. `POST /api/v1/user/login`（无鉴权）→ 全局四件套 → `UserHandler.Login`。
2. ShouldBindJSON 校验（username/password/device_id/platform）。
3. `LocalAuthUsecase.Login`：查 users → 锁定判定 → bcrypt 比对 → 成功清锁定。
4. `issueTokens`：签 UUID JWT（72h）+ 建 30 天 refresh 行（只存 hash）。
5. 回到 handler：`IssueOnLogin` 生成 session_id(UUID)，`SETEX auth:session:{uid} = {session_id,device_id,platform,created_at} TTL=SessionTTL()（默认 0 永久）`；白名单账号跳过本步。
6. 200 统一信封 `{token, refresh_token, session_id, user}`。客户端持久化三件套，之后请求带 `Authorization: Bearer`、`X-Session-ID`、`X-Device-ID`。

### 9.2 每次受保护请求

SA(ParseUUID/云校验) → DeviceSession Validate（真值表见 §4）→ [Gate 查 users 状态，仅 local] → handler 经 authctx 取 user_id → 业务。

### 9.3 单设备互踢

设备 B 登录 → `IssueOnLogin` 用同一 user_id **覆盖** Redis key（新 session_id+device_B）。设备 A 下一次请求：库存 device_B ≠ 携带的 device_A → `ErrSessionReplaced` → 401/10021 裸 JSON → 客户端清登录态。设备 A 若拿 refresh 调 refresh：`RenewOnRefresh` 发现设备不符同样 Replaced，**抢不回来**（除非重新登录再把 B 踢掉）。

### 9.4 refresh 全链路

1. 客户端收到 10023（access 过期/无效）→ `POST /user/refresh` {refresh_token, device_id?, session_id?, platform?}（公开路由）。
2. local：按 hash 查 refresh 行 → 过期/停用/注销校验 → 删旧行 → 发新 access + 新 refresh（轮换）。
3. 带了 device_id 时 `RenewOnRefresh`：同设备（或无记录、或客户端 session_id 与库存一致）→ 发**新 session_id** 并重置 Redis TTL；设备不符 → 10021 中止（此时 access/refresh 已在步骤 2 换发但不会返回给客户端？注意：local 实现是先刷 token 再续 session，续期失败时整个请求返回错误，新 refresh 行已删旧行、新行已建——**旧 refresh 已被消耗，客户端需用错误前拿不到的新凭证，实际只能重新登录**，⚠️ 这是轮换与设备校验非原子带来的边界，代码未回滚）。
4. supabase：token 刷新在云端；本地只做设备续期。
5. 不带 device_id 调 refresh：返回新 token 对，但不续 session；TTL=0 下 Redis 记录仍是旧 session_id，随后业务请求带旧 session_id+同 device → Validate 通过（同设备同 session 原样），但若客户端实现成刷新后本地清了 session_id 就会 10022。

### 9.5 logout 与注销

- **logout**：SA 链已验过会话 → handler 调 `RevokeOnLogout`（豁免 no-op；否则再 Validate 一次然后 DEL Redis key）→ `sessionAuthUC.Logout(accessToken)`：local 删该用户全部 refresh 行（云端其他设备的 refresh 也一并失效，但 Redis 互踢记录此时已删）；supabase 调 GoTrue logout。之后 access JWT 在 local 模式虽未到期也无法通过 Validate（Redis 无 key → 10022）。
- **deactivate**（仅 local）：软删 users.deleted_at + 删 refresh 行；不删 Redis session（同请求随后的 logout 语义由客户端另调；⚠️ 单调 deactivate 后 Redis key 仍在，Gate 查 deleted_at 会拦 403，下次登录直接未注册）。

### 9.6 白名单/测试号豁免链路

`IsExempt` 命中时：Issue 不写库只回 session_id；Validate 永远 nil（不看头）；Renew 不写库并尽量原样返回 session_id；Revoke no-op。因此白名单账号多设备并行，且其请求里 X-Session-ID/X-Device-ID 随便填。测试号额外要求 APP_ENV 非 prod 且配置齐 dev_test_*。

## 10. 占位/边界清单（零杜撰）

1. **短信是 dev-only 占位**：两种后端的 SendPhoneOTP 对测试号都是 no-op，固定 OTP 由配置给出；真实短信通道未接入，生产返回「短信登录暂未开放」。
2. **微信/华为仅 local**：云模式下 UC 为 nil，handler 回 503；第三方 http 调用失败的用户信息获取（微信 fetchProfile）静默吞掉。
3. **华为 openID 不落库**：`_ = openID // 仅联调用`，账号主键认 UnionID。
4. **云模式无账号 Gate、无锁定**：注销/停用拦截只在 local 生效。
5. **JWT 无吊销列表**：local logout 靠删 Redis 会话让 JWT 失效，不是 JWT 本身失效；若有路径绕过 SA 直接信 JWT 则注销不生效（当前路由无此路径）。
6. `ValidateAccessToken` 用 `http.DefaultClient` 无独立超时；登录类接口有 20s `withAuthTimeout`。
7. refresh 轮换与设备续期非原子（§9.4 第 3 点）。
8. 老 uint-JWT 体系（`Claims/Generate/Parse/middleware.Auth/GetUserID`）在现网路由无挂载点。
9. 会员华为服务端通知路由暂挂鉴权组（见 [04](04-HTTP路由与中间件.md) §2.7），与认证无关但属鉴权边界。

## 11. 学习要点回顾

1. **一个接口、两套实现**：`SessionAuth`/`PhoneOTPAuth` 让 handler 与 provider 解耦，切换只改装配；输出统一成 `SupabaseAuthOutput`，Flutter 无感。
2. **单设备 = 一用户一 Redis key 的覆盖写**：互踢不是主动推送，而是旧设备下次请求时被动发现；10021（顶替）与 10022（无效）必须分开，客户端 UX 不同。
3. **三层凭证各管一段**：JWT/云 token 管「身份与短时准入」、refresh token 管「续期」（30 天+一次性轮换+只存 hash）、device session 管「设备唯一性」；三者失效策略独立。
4. **TTL=0 只作用于 Redis 会话**：默认配置下 session 永久驻留，顶替/logout 是唯一清理方式；JWT 仍 72h 过期，refresh 仍是 30 天。
5. **白名单短路一切**：豁免账号不碰 Redis，天然多端；测试号豁免还额外绑定非 prod 环境。
6. **安全细节**：bcrypt 哈希、refresh 只存 SHA256、JWT 强制 HS256 防 alg 混淆、登录失败 5 次锁 15 分钟、service_role 才区分「未注册/密码错」防账号枚举。
7. **锁定不踢在线用户**：登录入口与请求入口的状态判定故意不同（loginBlockReason 拦 status=2，AllowsRequest 不拦）。
8. **错误码分层**：10002 密码错误、10021/10022 会话、10023 token、10024 OTP——客户端按码分支，不依赖中文文案。
9. **导入环治理**：会话身份读写放 authctx 叶子包，中间件与业务域共享同一组 context key，两种 provider 写入口完全一致。
