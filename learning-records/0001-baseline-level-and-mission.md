# 基线：Go 能写但靠查，目标是面试表达

2026-10-29 建立工作区时自述：方向选「Go 后端分层 / Clean Architecture」，真实目标是**面试与技术表达**（能讲清取舍、扛住追问），当前水平是**能写但靠查**（channel / context / interface 常查文档）。

## Evidence

- 三项选择均由其在 /teach 问卷中明确勾选，非推断。
- 仓库侧旁证：已有 `docs/feishu/go-deep-dive/` 18 篇函数级学习笔记，说明读得懂代码、但「说出来」这条链还没被训练过。

## Implications

- **不要**从抽象分层概念开讲：语法不熟时讲架构等于讲口号，工作记忆会被语法查询占满。
- **要**把每课锚在「一条可运行的验证命令 + 一段可说出口的答案」上：既补语法接缝，又直接服务表达目标。
- 面试导向意味着后续要练**反驳与限定**（例如 "accept interfaces, return structs" 并非铁律），只会背原则在追问下会崩。
