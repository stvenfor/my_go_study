# 2026-10-21

## 让 `make lan-up`（Docker 全栈）真正跑通

本机 Clash 代理 + Docker Desktop 叠加下，逐层排障直至 10 个容器全部 healthy、`GET /health` 200。根因与修法：

1. **Docker Hub 拉取失败**：`auth.docker.io`（Docker Hub token 服务器）经 Clash 不通（`registry-1.docker.io` 通、`auth.docker.io` 不通）→ docker.io 镜像 100% 卡在拿 token。
   - 修法：`~/.docker/daemon.json` 加 `"registry-mirrors": ["https://docker.m.daocloud.io"]`（daocloud 自带鉴权、直连 0.06s 可达）。**该键重启后能持久**（与 `proxies` 不同）。
2. **daocloud 并发限流**：8 镜像并行拉触发 `请求过于频繁`。修法：改**逐个顺序拉**（带重试），全部缓存后再 `make lan-up`。
3. **sandbox 里 `sed -i ''` 报错**（`No such file or directory`）：本环境 `sed` 是 **toybox 0.8.13**（WorkBuddy shim，经 `BASH_ENV=.../shell-runtime-bash-env.sh` 重新注入，普通改 PATH 压不住）。`scripts/sync-lan-ip.sh` 因此挂。
   - 修法（不改项目脚本）：跑 make 时 `env -u BASH_ENV PATH="/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin:/usr/local/go/bin:$HOME/.local/bin"` → 落到系统 BSD `sed`，`-i ''` 正常。用户真实终端不会触发此问题。
4. **Docker 构建拉 Go 依赖/apk 失败**：构建容器网络被强制走 Clash 代理，而 Clash **拒绝** `goproxy.cn`、`proxy.golang.org`、`goproxy.io`、`mirrors.aliyun.com`、`dl-cdn.alpinelinux.org`（经 Clash `http=000`，但**直连均 200**）。
   - 修法：`docker/Dockerfile` 两个 stage 加 `ENV NO_PROXY=goproxy.cn,dl-cdn.alpinelinux.org,...`，让 `apk add` 与 `go mod download` 直连绕过 Clash。运行 make 时传 `GOPROXY=https://goproxy.cn`（去掉 `,direct`，避免回落被墙的 github）。
5. **`go.work` / `go.work.sum` 缺失**：二者被 `.gitignore`，本 checkout 从未生成；Dockerfile 需要 5 模块工作区。
   - 修法：手写 `go.work`（`go 1.25.0`，use ./common ./core ./model ./app ./thunder）+ 空 `go.work.sum`。**go.work 必须声明 `go 1.25.0`**（镜像是 `golang:1.25-alpine` + `GOTOOLCHAIN=local`，写 1.26 会因本地 go1.26.4 生成错版本而构建失败）。
6. **app/worker 冷启动 Exited(1)**：`rabbitmq-diagnostics ping` healthy 但 AMQP 5672 监听慢一拍，app 连不上直接退出（无重试）。
   - 修法：`docker-compose.yml` 给 app/worker 加 `restart: unless-stopped` 自愈；当前实例手动 `up -d --no-build app worker` 已 healthy。
